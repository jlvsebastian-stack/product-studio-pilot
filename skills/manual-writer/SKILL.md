# Manual Writer

## Planning Contract

For outline planning only, preserve the approved procedure sequence. Name the operator, trigger, prerequisites, normal steps, observable completion and necessary exception or handoff for each unit. Do not draft the manual or introduce unrelated policies, troubleshooting inventories or approval gates.

## Production Contract

Make each task easy to find and carry out. Give its purpose, when to use it, essential prerequisites, ordered actions and expected result. Include roles or responsibilities only when the creator's actual process needs them.

Use consistent names for tools, fields and outputs. Provide complete examples, useful reference tables and decision conditions. Explain common failure signs and the corresponding recovery action. For an SOP, make the trigger, responsible role, required record and completion check clear when those facts are known.

Keep reference details separate from the shortest normal procedure. Do not guess interface controls or invent system behavior; verify topic-specific facts when needed and identify unknown requirements. This format supports repeatable use, not chapter-by-chapter teaching or presentation copy. Keep the approved scope and change only authorized passages.

Start the common procedure with what the reader needs in hand and the shortest correct path. Each numbered step names the actor's action, the exact object or field involved and the result needed before the next step. Include branch conditions beside the step where they matter. Do not bury required decisions in background paragraphs or use a later step's output before it exists.

For a repeated task, supply the actual reusable record or table promised by the plan, with a completed illustrative example. Separate quick reference from explanation. Troubleshooting names the visible symptom, likely relevant condition, safe recovery and how to verify recovery. Do not invent a reset, delete action or escalation contact to make a procedure look complete.

Within the current turn, walk through the procedure as a beginner using only the information supplied. Check prerequisites, handoffs, examples and recognizable completion. Repair gaps before returning it; no added interview, compulsory checklist ceremony or extra approval. Focused edits leave other procedures intact.

## Visual Design

<!-- Modified 2026-11-02: design guidance adapted from Anthropic skills (Apache-2.0), pinned at ca45fc496a3436251f191354091d557da31c15b5. See THIRD_PARTY_NOTICES.md. -->

- Use a calm, consistent reference layout with real headings, easy-to-find procedures and numbering only for ordered actions. Match the creator’s visual direction without sacrificing quick lookup.
- Place prerequisites and material warnings before the affected action; distinguish actions, expected results and recovery through spacing and labels. Use native tables or diagrams for actual relationships.
- Check the real file for navigation, split procedures, stranded warnings and readable tables. Keep complete instructions editable; decorative variation must not obscure a repeatable task.

## Final Quality Review

- Walk the normal procedure and a relevant recovery using only the manual: prerequisites, exact actions, handoffs and recognizable completion must agree.
- Inspect actual document navigation, step numbering, reference tables and page breaks; keep a step's essential condition findable and fix safe formatting defects.
- Check supplied records and worked examples are usable. Preserve approved procedures and system facts; report substantive gaps and grounded optional improvements under the shared review boundaries.
